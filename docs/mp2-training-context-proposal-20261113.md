# MP2: training-context expansion feasibility proposal

Proposed Codex task on a separate branch `codex/training-context-mp2-20261113`, starting at OA2 result commit `9afc9761fbdd6d96b08bc96a9d0c8f6aa9c57dc3`. Own new `mp2_select.py`, `mp2_worker.py`, `run_training_context_mp2.py`, `audit_training_context_mp2.py`, focused tests and compact prospective/results documents only. No peer, native controller, body, sensory, learner, evaluator or old experiment files changed. This is preparation, not an allocated run.

Evidence and hypothesis: MP1 selected a policy improving both training returns by construction, but failed frozen physical/retention criteria; OA2 reproduced the original decisions and found the alternate load reference selects identical policies. Hypothesis to test: a two-context acceptance panel is too narrow for this fixed eight-policy search. Expanded training acceptance might reject a context-specific update or identify a different eligible whole policy. This does not assume that more contexts will produce standing or that this hypothesis explains all failures.

Hold fixed the documented MP1 experimental parent, all eight existing four-direction/sign probe checkpoints, original1percent reference-relative perturbation, original PS1 objective,50ms warmup,5s native neural episodes, body/muscle/adhesion/sensory settings and frozen physical gates. No new perturbation search, weight averaging, motor bypass, reward correction or online plasticity. Parent remains experimental, not validated-best. Original topology/sign/bounds and exact full-graph imports remain mandatory.

Reuse only sealed complete training evidence from seeds1010/1011. Proposed additional TRAIN seeds1012/1013/1014/1015 must pass a signed preallocation inventory of available report/context headers and protocol declarations, with the scope/limitations of that inventory recorded. If prior use is found, STOP and amend the plan before running; do not silently replace seeds. Final reserved seeds10/11/200/201/202 remain untouched. No old DEV or fresh frozen result is added to training.

Proposed allocation: one exact native replay baseline at seed1010 from the original parent, then four new contexts each with parent and all eight fixed probe policies:37workers maximum. Use the existing contained Windows process-tree watchdog; no retries, skipped cells or partial-checkpoint acceptance.

Each new context uses identical neural RNG schedule for parent and eight probes; all motor commands arise from actual native neural execution. Contexts vary the existing stochastic neural seed; this alone does not vary terrain, body starts or perturbations, and is not a full balance/walking robustness test.

After all complete training data, independently reproduce the original two-context selection. For expanded selection calculate, for each of eight policies, the minimum original-objective return gain relative to its same-seed parent across all six training contexts. Apply unchanged strict margin>1e-6, canonical first-index ties, otherwise parent fallback; calculate a separate reward-reversed control from the same data. Persist the entire return panel and provenance/selection state locally and reload it to reproduce selection. Any selected model must be byte-identical to an existing probe or the parent, with a new sidecar; never overwrite an existing checkpoint. No independently trained weights are merged.

Decision-dependent end of this allocation: if expanded acceptance falls back, record no eligible update in this finite policy panel; if it chooses the identical MP1 policy, record that broader acceptance did not change the model and avoid duplicate physical evaluation. If it selects a different policy, retain it strictly as an experimental training candidate. A separate prospective allocation must evaluate it against parent, old MP1 and appropriate reversed/gradient controls on predeclared independent contexts and unchanged physical/anatomical/retention gates. No physical evaluation or capability promotion is allocated by this feasibility proposal, and training acceptance cannot establish efficacy.

Required preallocation checks: selector tests for arbitrary exactly six registered contexts, missing/duplicate/incomplete/wrong-role/held-out data rejection, bounded returns, strict-margin/tie/fallback/reversed cases, exact two-context reproduction, actual checkpoint import/topology/sign/bounds checks, immutable output/provenance guards, resource/lease/awake/timeout/failure cleanup and no-retry controls. Independent post-run audit must recompute returns/selection/state and verify all full-horizon receipts, saved candidates and guards. Stop on any failure.

Public records contain code, prospective plan and compact verdict only. Raw data, per-case return tables, private provenance maps, archives/receipts remain local unless separately approved. This task is not a claim of standing, balance, walking, environmental learning, retained improvement or biological validation.
